## Key Findings

### 1. Phase-Centric Org Creates Duplication
Several topics are addressed in multiple phases:
- **Agent format learning:** phase-4 journal + phase-4 critical learnings + phase-5 results + phase-6 findings
- **SharePoint capabilities:** phase-3 discovery + phase-4 probes + phase-5 evaluation
- **Canonical contract:** phase-1 specs + phase-2 hardening + phase-4.5 refactor

**Recommendation:** Move durable conclusions to eternal domains; keep phase evidence in place.

### 2. Research vs. Phase Evidence Not Clearly Separated
Some files like `research-summary-phase3-sharepoint-write-capability-discovery.md` conflate exploratory research with phase-scoped discovery.

**Recommendation:** 
- Move synthesized, generalizable findings to research domains
- Archive phase-specific discovery to `docs/reports/phase-N-*/`
- Use metadata to track provenance

### 3. External Source References Lack Metadata
Research summaries cite Microsoft docs without retrieval dates, versions, or retrieval methods.

**Recommendation:** Add `.metadata.json` to each research file listing external sources with date, version, access method.

### 4. Legacy References Are Disorganized
`docs/architecture/docx-to-content-legacy-references/` is valuable historical record but not discoverable from main research nav.

**Recommendation:** Keep legacy folder; add README linking it to the active architecture; add `.provenance.json` showing why each file was archived.

### 5. Experiment Protocols Are Scattered
Evaluation cases and experiment specs live in `tools/phase-*/evaluations/` not in research or discovery folders.

**Recommendation:** Archive closed experiments to `research/research-experimentation/experiments-closed/` with a summary linking back to phase evidence.
