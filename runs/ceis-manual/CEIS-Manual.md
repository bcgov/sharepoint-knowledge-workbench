## DATA CAPTURE STANDARDS 

The Civil Electronic Information system (CEIS) was implemented as the civil provincial case tracking system in 2004.

With the addition of our electronic initiatives, e-filing, e-registry, Court Services Online, and the integrated court vision, it is imperative to set formal data capture standards and consistently maintain these standards at each court location across the province. These enhanced standards have been approved by the executive and senior district and local managers support the change process to transition to these standards.

The following timelines and content are mandatory CEIS standards as of September 1st, 2007:

### **Data Capture Requirements**

*All documents are mandatory*

- Each document filed per court file must be entered in CEIS.

*All documents entered within 24 hours*

NOTE - 24 hours refers to elapsed clock hours versus business hours

*All results from court entered the same business day*

NOTE - 24 hours refers to elapsed clock hours versus business hours

### **Data Element Requirements**

[Filing party]{.underline}

- The filing party must be entered on the Parties Filed by tab in the Documents module for each document entered into CEIS.

[Date filed]{.underline}

- Each document filed through Supreme Court Scheduling must be entered in CEIS with the date that appears on the SCSS stamp. Do not re-stamp these documents with the registry stamp.

[Enter issues for all documents]{.underline}

- Each document that contains an issue must have that issue entered. Issues must be entered at the time the document is entered, whether the document is scheduled for a court appearance or not.

- To assist registry staff in selecting the correct issue code, the issue table displays only issues that apply to the level and class of the current file.

[Enter court dates received from trial division before appearance date]{.underline}

- Each document from Supreme Court Trial Scheduling with a court date must be entered prior to the appearance date. This includes both the document and court date.

[Enter Act per initiating document]{.underline}

- When a matter is commenced pursuant to a specific Act, that Act, when known, must be entered in the Act field on the Document Details screen. The Act must be entered against the initiating document for all levels and classes of files.

[Use of code \'Other\']{.underline}

- Not all court hearings or appearances fall under a pre-existing document or issue code. The code \'Other\' is to be entered where there are existing applicable document and issue codes. In the event the appropriate document or issue code does not exist, notify the [AG CEIS Support](mailto:Courts.Ceis@gov.bc.ca) so the code can be added.

[Claim value]{.underline}

- For all Small Claims matters the value of the claim and counterclaim must be entered in CEIS. Whenever a claim value is provided on Supreme Court initiating documents, the value must be entered in CEIS.

[Scheduling multiple documents]{.underline}

Where there is one appearance for multiple documents, ensure that all documents are scheduled together against that appearance. Do not schedule a separate appearance for each document unless the appearance reason differs. For example: for a Small Claims settlement conference, ensure that the Notice of Claim and Reply with Counterclaim are scheduled together, not individually.

## PUBLIC INQUIRY GUIDELINES

### **Searching files at your own location**

If you have a Public Access Terminal (PAT), refer the public to it. If they are uncomfortable using the PAT or your location does not have one, you may do a search for them. Search fees are only charged to people who are not a party to the action.

### **Searching files at other locations**

You must exercise discretion when providing information from another registry location. If they are not a party to the action, refer them to the originating registry for further information. If an individual requests information about the terms of an order, you have the ability to print these details directly from CEIS; parties to the action are entitled to this information free of charge. Requests made by anyone who is not a party to the action are subject to the \$8 search fee. However, any specific details concerning the file should be referred to the originating court registry.

Please review the Provincial Court's [Access to Court Records Policy](https://www.provincialcourt.bc.ca/downloads/public%20and%20media%20access%20policies/ACC-2%20-%20Access%20to%20Court%20Records.pdf) that was updated December 2019 to ensure you are familiar with the access restrictions on files and documents.

You may also review the [Access to Provincial Family and Supreme Court Family files](https://portal.jag.gov.bc.ca/portal/page/portal/CSB_Home/document_repository/private/branch_info/courtrecord/guidelines-id-requirements-family-files-disclosure-information.pdf) and for Additional information review the [Records Access Policies page](https://portal.jag.gov.bc.ca/portal/page/portal/CSB_Home/private/Court_Record_Access/intro) .

## FILE ACCESS 

### **File Access Levels** 

An \"Access Level\" code entered at the time of file initiation and determines who will have access to that file.

Access to a file is differentiated between internal and external users. Internal users are court staff, while external users are members of the public.

The access levels are:

- **General Access** to all data. (All files will have general access with the exception of Supreme Family Law, Provincial Family, Supreme Adoption, and Supreme Probate.

- **Temporary Restricted Access** restricts access to a file for a limited time during processing. (Internal users will have full access; external users will only be able to access file numbers (Adoption is the exception)

*NOTE -* By default, all family matters are set to Restricted Access when the file is initiated.

In addition to the above access restrictions, further restrictions may be set by order of the court:

- **Publication Ban** restricts access so that external users will not be able to view the file.

- **Sealed By Court** Order means an order has been made sealing the file or document if applicable.

In addition to access levels at the file level, the same types of access restrictions can be set for individual documents.

CEIS automatically sets access restrictions based on the class and category of file. For example, if a Supreme Court file is classed as Adoption, it can only be viewed by users who have the security permissions to access adoption files.

## INITIATE A FILE

Specific mandatory data must be entered before a new file can be saved.

CEIS will check that the following details have been entered:

- File Details

- Party and Role (at least one party and role)

- Initiating Document

If you abandon the Initiate File sequence without having entered the above minimum details, this warning message will appear:

![](output/ceis-manual/images/media/image17.gif){width="3.158333333333333in" height="0.8333333333333334in"}If you select \"Yes\", the file will be deleted from the database and all details must be entered again from the beginning. If you select \"No\", the screen stays open so you can continue initiating the file.

### **How to Initiate a File**

![](output/ceis-manual/images/media/image18.png){width="5.469444444444444in" height="2.9305555555555554in"}The first step in initiating a file is to record the file identification details.

NOTE - All the fields in the File Identification screen are mandatory

NOTE -- The Date opened should never be AFTER the filed date of the initiating document. They should be the same day. The only exception to that rule is file amalgamation and the initiating document on the amalgamated file will be different that the new file.

1.  **Court File Number**: The file number that corresponds to the physical file jacket in your registry. This field uniquely identifies a file across the province. (At this time, exactly how new files are to be numbered is left to the discretion of individual regions.)

2.  **Level**: The level of court: Supreme (S) or Provincial (P).

3.  **Class**: This is the file type.

When initiating a Provincial Court civil file, the following classes must be used:

  ----------------------------------------------------------------------------
  C   Small Claims                       F   Family
  --- ------------------------------ --- --- ---------------------------------

### **Re-Initiating Old or Destroyed Files**

In the event you find yourself in a circumstance where a file that was properly destroyed after 25+ years and is not in CEIS but is being resurrected and has an upcoming hearing date in a court location. How should you manage this?

Although there are no real statistical requirements, we recommend initiating the file under the original file number. Although the physical file has been destroyed, once a \'case\' has a number it should keep it wherever possible, providing it\'s still in the same level and class.

In the File Details Comment section, fill in the detailed that this file is being resurrected and was originally opened in DayMonthYear.

The purpose is to have a full story of the file within the file, and also as this is new action on the file, we should have a newer date to re-set possible retention time frames for this file.

As for the Documents, if we are accepting old documents, enter them as the date of the new opened date, and in the Document Detail Comments, place the original filing date if known.

**Change of Individual's Name Pursuant to Court Order**

1.  In the *Parties* screen, highlight the party against whom the order applies.

For a divorce file, click the *Also Known As* tab and enter the new name using the code \"NKA\" for \"now known as\", so the married name (former name) appears before the current name when a Certificate of Divorce is printed.

### **Scheduling Appearances -- Files Transferred for All Purposes**

For files transferred from one location to another for all purposes, the receiving location schedules the court appearance at their location. The system **will not** allow the sending location to schedule an appearance to the receiving location.

If the sending location has scheduled such an appearance, a pop-up box will appear when the transfer for all purposes is saved; it will not allow the transfer until the appearance has been resulted or deleted. The rationale for this is that the sending location is not familiar with which courtroom the matter should be scheduled into at the receiving location.

However, there are times when a file has been adjourned to a future date via CCD and CEIS is still allowing the transfer of the file, which results in an email to CEIS Support to correct the appearance.

### **Scheduling Appearances -- Files Transferred for Hearing Purposes**

If the file is only being sent for a hearing event, the file will be *scheduled* to the receiving location rather than actually being *transferred*. The receiving location then records the results of the appearance at their location (which includes adding any orders or scheduling future appearances).

However, in most cases, the physical file will be sent as well. This involves an additional step in CEIS to monitor and track the file. Check out []{.mark}[[TRANSFERS]{.underline}](#transfers) for that step.

### **Reserved Judgments** 

After an appearance a Judge reserves the right to provide their Judgment on record at a future appearance or in writing by way of Reasons for Judgment.

If the Judge will provide Judgment Orally, a further date will be scheduled in Court. The reason for the next appearance will be **DEC**.

If the Judge will provide Judgment in writing we follow these steps:

1)  The Appearance result will be RJ.

2)  When the Judge completes their Reasons for Judgment, the Original plus copies will be provided to the Registry.

3)  Data enter the Reasons for Judgment as a Document (Code RFJ)

4)  Go to the Appearance Tab, select the Appearance that has the result of RJ, and Record Result.

5)  Via Record Results, go to the Results Tab and add the Order and follow regular processes.

It is important that the Order is added this way, as the Judiciary run Reason for Judgment reports, and this process will remove this Judgment from their list.

## ORDERS

It is important to understand the following concepts:

- All known orders for a civil file must be entered in CEIS.

- Typically, when an order is made as a result of a court hearing, only the order type, date granted, terms of order, POR/CFC tracking, and adjudicator is entered. When the order is filed at the registry or produced and signed, the order details are updated with the date entered, and any further information.

- Protection Orders are **ALWAYS** stand alone orders.

There are **three** methods of entering orders:

- via the Orders module of Maintain File --- click Orders from the left-hand sidebar menu.

- via the Documents module of Maintain File --- click the ADD ORDER button in the main Documents screen.

- via the Record Results module --- click the ADD ORDER button in the Record Document and Issue Results screen.

Regardless of which method you choose to access the *Orders* screen, once in the Orders screen, the procedure for entering an order is identical.

The **Orders** screen consists of five tabs:

- **Order Details**: This screen lists all orders (if any) that have been entered against the file. From this screen you can add a new order or edit an existing one. This is where you enter or edit the details of the order. Once you click SAVE the *Order Terms* screen will appear.

- **Order Terms**: In this screen you will enter the terms of the order in conformance with our best practices.

- **POR/CFC**: If an order is to be sent to the Protection Order Registry (POR) or the Canadian Firearms Centre (CFC), additional information needs to be entered in this screen. This tab will only be activated if the **Protection Order** or **Firearms Order** boxes are selected in the *Order Details* screen.

- **Referral Tracking**: This screen tracks referrals against a selected order on the file. (An order may have zero to many referrals during the life of the file.)

- **Seal Order Details:** This screen is used when a Judge makes an order sealing documents or a file. The tab will be activated after the Seal Order box is selected.

### **Order Details** 

The Order Details screen is where you enter or update information about the order such as order type/description, date granted, and adjudicator name.

To edit/update an existing order, highlight the one you wish to edit/update in the Order Details screen and double-click. The details of the order will then populate the fields below; from here you can edit information as required.

To add a new order, click the Add Order tab; you\'ll be taken automatically to the first field to be populated in the lower portion of the screen, which is Document Access. This field will automatically populate from the file details. The fields which are mandatory will have an asterisk (\*) beside them.

# **PROTECTION ORDERS**

The family law protection order is a civil order made in family court that contains a condition that affords safety and security to a specified person or persons. It must include a provision that restricts the activities of a party to prevent harassment, harm, or communication with another person. Orders must be made under s. 183 of the FLA to be called a protection order under the FLA. Protection or restraining orders may also be made in family court under the *Child Family and Community Service Act*, the *Family Maintenance Enforcement Act* and the *Adult Guardianship Act*.

It is a criminal offense for the person named in the order to disobey ("breach") it. If they do so, the police can enforce the order under the [Criminal Code](http://laws-lois.justice.gc.ca/eng/acts/C-46/) and the individual may face significant consequences.

### **Rules of a Protection Order**

[Protection Orders MUST:]{.underline}

- Have full complete names of the parties retrained and protected

- Have a date of birth for all parties retrained and protected

- Have complete addresses (if an address is mentioned in the POR)

- Have complete sentences (using proper punctuation)

- Be a separate order from any other terms such as child support or parenting time

- Be sent SAME DAY to the Protection Order Registry via POR Details in CEIS.

- Personally served if the restrained party was NOT present when the order was made (via Process Servers unless otherwise directed by your Judge)

There are several different reasons why files are transferred, and it\'s important to understand the corresponding business rules around access and who can update a file once it\'s transferred. This is for the CEIS procedures only, for further procedures if sending physical documents, review the respective [Manual](https://csb.jag.gov.bc.ca/Pages/Manuals.aspx).

### **Transfer for All Purposes**

When files are transferred for all purposes, the receiving location is responsible for scheduling the court appearance at their location.

When a file is transferred *for all purposes*, the sending location\'s file becomes \"Read-Only\" as soon as the transfer is accepted from the receiving registry. This means you will not be able to edit any of the data fields in that file.

However, the receiving registry assigns it a new file number, and then all existing and new data is recorded against this new file.

The old file number will still exist electronically, with all the associated data up to the point of the transfer, but the data will be \"frozen\" and the sending location will only be able to view the old file, not edit it.

The receiving location will be able to view the history of all appearances on the file through the \"Appearance History\" tab in the *Court Appearances* screen.

### **Transfer for an Appeal**

When a file is transferred from Provincial Court to Supreme Court *for an appeal*, the Provincial Court file remains open for data entry in CEIS, since subsequent hearings may still be ongoing.

However, data from the Provincial Court file should *not* be transferred into the Supreme Court file. Since an appeal is initiated with a Notice of Appeal, the Supreme Court must first initiate a new file. Then the Provincial Court electronically transfers the file, and the Supreme Court accepts the file into the *existing* Supreme Court file number (assigned to it with the Notice of Appeal).

### **Transfers from Small Claims to Supreme Court For All Purposes**

The following mandatory best practice applies when a Provincial Small Claims file is transferred to Supreme Court for all purposes:

When a file transfer for all purposes from Provincial Court Small Claims to Supreme Court General is accepted, the role type of \"Plaintiff\" should be added to the claimant(s)\' [[Changing Party]{.underline} **Roles**](#changing-party-roles).

This role is in addition to the existing role(s). The existing role of \"Claimant\" should not be overwritten, for two reasons:

> • For data management purposes
>
> • To accurately reflect the history of the file

NOTE -- If the transfer is from Supreme Court to Provincial Small Claims, the additional role type of \"Claimant\" is added to the plaintiff(s)\' role.

### **Transfer Between Multiple Registries**

Best Practices when transferring a file between registries for hearing purposes in the following scenario:

• Registry A electronically transfers their file to Registry B for a hearing event. They also forward the physical file via house mail to Registry B.

• Registry B accepts the transfer and conducts the hearing.

• The judge at Registry B orders that the file be transferred to Registry C for further hearing.

Although the Judge at Registry B ordered that the file be transferred to Registry C for hearing, Registry B is unable to electronically transfer the file to Registry C in CEIS.

The ***[mandatory best practice]{.underline}*** to be followed in this scenario is:

1.  Registry B should contact Registry A via email or telephone and advise them that the judge has ordered that the file be transferred to Registry C for a hearing event.

2.  Registry B should return the file electronically in CEIS to Registry A.

3.  After accepting the returned file, Registry A should electronically transfer the file in CEIS to Registry C. They should include a comment in the \"Comments\" section in the Hearings Sent screen, indicating that Registry B will be sending the physical file to them.

4.  Registry B will send the physical file to Registry C, with a memo that indicates that Registry A will be transferring the file to them electronically in CEIS.

5.  After the hearing event, unless otherwise ordered, Registry C will electronically transfer the file back to Registry A and send the physical file to Registry A via house mail.

### **Transfer out of Province**

Although we do not connect to other provinces applications, we do have a means to capture a transfer within CEIS to ensure we know what happened to the file. We would transfer out just like normal, only difference is we will not get a received status back.

In the event this same file is returned from the other province and we need to accept it back -- connect with CEIS Support and we will reverse this transfer. If this happens, we need to make a notation in the File Details Comment section that it was transferred to another province and returned, in case there are further orders, documents or actions within the file from said province. We have a way of understanding the full story of the file.

1.  An order is made by the court that two or more files be amalgamated. (The judge will identify which of the files will be the lead file (File A), and will also identify the new style of cause.)

2.  Remove the original physical contents of File B (the secondary file) and place them in File A (the lead file). Leave a copy of the amalgamation order in File B.

3.  Notate on the File B file folder (the location to be determined by local registry practice) that the file has been amalgamated with File A (include file number).

7.  If new documents are submitted with File B\'s file number, manually change the document to show File A\'s file number. Do not reject the documents because the file number is incorrect.

8.  All documents that are filed subsequent to the court order must be entered against File A.

# **CEIS ACCESS LEVELS**

Users are assigned access roles in CEIS for each level and class of files. These access roles determine the files they can access in CEIS, and whether or not they can perform various data entry functions.

Once a user has access to a particular registry location, they will have the same access to the files of all associated circuit courts for that location. Also, if the user\'s home location is the receiving location for a location that has been closed, the user will have the same access to the files of the closed location. (For example, Nanaimo is the receiving location for Parksville, so Nanaimo users will have the same access to Parksville files as they have to their own registry files.)

**The access roles are:**

- No access (to selected classes)

- Read Only access (to selected classes)

- Full Update access (to selected classes, other than the calendar)

- System Administrator access

- Maintain Calendar access only

- Sheriff access

Please speak with your manager or supervisor if your access role needs to be changed.

### **User Role (Type)**

In some regards, access is affected by the user role, as well as the access role. For example, only users assigned the user role of \"Court Clerk\" are able to record results in the *In-Court Module*, if they have the required access role of \"Full Update\"; a user assigned the user role of \"Clerk/Recorder\" will not be able to record appearance results in the *In-Court Module*, even though the user still has the required access role of \"Full Update\".

### **Sheriff Access**

A user role (type) of \"Sheriff\" allows Sheriff Services personnel to create/edit/modify/delete sheriff comments only, even for transferred-in files. The Sheriff access role is \"Read Only\", which applies to all other aspects of the application.

### ***Extended Access***

Users with extended access can update file details in CEIS for files transferred for appearance purposes, whereas users with \"Full Update\" access can only update the appearance results on transferred files.

Only a limited amount of experiences CEIS Users per site are provided with extended access.

It is the responsibility of the site contacts to advise the [AG CEIS Support Group](mailto:courts.ceis@gov.bc.ca) of the users at their location who should have access to the files of all court locations in the province.
