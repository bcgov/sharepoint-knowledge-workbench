# TRANSFERS

There are several different reasons why files are transferred, and it\'s important to understand the corresponding business rules around access and who can update a file once it\'s transferred. This is for the CEIS procedures only, for further procedures if sending physical documents, review the respective [Manual](https://csb.jag.gov.bc.ca/Pages/Manuals.aspx).



### Transfer for All Purposes

When files are transferred for all purposes, the receiving location is responsible for scheduling the court appearance at their location.

When a file is transferred *for all purposes*, the sending location\'s file becomes \"Read-Only\" as soon as the transfer is accepted from the receiving registry. This means you will not be able to edit any of the data fields in that file.

However, the receiving registry assigns it a new file number, and then all existing and new data is recorded against this new file.

The old file number will still exist electronically, with all the associated data up to the point of the transfer, but the data will be \"frozen\" and the sending location will only be able to view the old file, not edit it.

The receiving location will be able to view the history of all appearances on the file through the \"Appearance History\" tab in the *Court Appearances* screen.

### Transfer for Hearing Only

Any file can be scheduled to another location *for a hearing event*. Hearing events held at other locations will be scheduled to the receiving location.

The sending location will create a Transfer For Hearing Event record in the Transfers module. This is done to track the physical file and to produce a foreign file transfer memo. It will not create an electronic transfer like an all-purposes transfer. In most circumstances, the physical file must still be sent as well.

The receiving location will record the results of the appearance at their location and send the physical file back to the home location when completed.

To assist registries in monitoring files scheduled to their location, a report called Appearances - Other Locations can be printed daily.

Foreign files that are not resulted will appear on the appearance location\'s Appearance Exception Report.

The Sheriff Report will also show all files scheduled at the location on a selected date, including transferred-in files.

### Transfer for an Appeal

When a file is transferred from Provincial Court to Supreme Court *for an appeal*, the Provincial Court file remains open for data entry in CEIS, since subsequent hearings may still be ongoing.

However, data from the Provincial Court file should *not* be transferred into the Supreme Court file. Since an appeal is initiated with a Notice of Appeal, the Supreme Court must first initiate a new file. Then the Provincial Court electronically transfers the file, and the Supreme Court accepts the file into the *existing* Supreme Court file number (assigned to it with the Notice of Appeal).



### Transfers from Small Claims to Supreme Court For All Purposes

The following mandatory best practice applies when a Provincial Small Claims file is transferred to Supreme Court for all purposes:

When a file transfer for all purposes from Provincial Court Small Claims to Supreme Court General is accepted, the role type of \"Plaintiff\" should be added to the claimant(s)\' [Changing Party **Roles**](#changing-party-roles).

This role is in addition to the existing role(s). The existing role of \"Claimant\" should not be overwritten, for two reasons:

> • For data management purposes
>
> • To accurately reflect the history of the file

NOTE -- If the transfer is from Supreme Court to Provincial Small Claims, the additional role type of \"Claimant\" is added to the plaintiff(s)\' role.



### Transfer Between Multiple Registries

Best Practices when transferring a file between registries for hearing purposes in the following scenario:

• Registry A electronically transfers their file to Registry B for a hearing event. They also forward the physical file via house mail to Registry B.

• Registry B accepts the transfer and conducts the hearing.

• The judge at Registry B orders that the file be transferred to Registry C for further hearing.

Although the Judge at Registry B ordered that the file be transferred to Registry C for hearing, Registry B is unable to electronically transfer the file to Registry C in CEIS.

The ***mandatory best practice*** to be followed in this scenario is:

1.  Registry B should contact Registry A via email or telephone and advise them that the judge has ordered that the file be transferred to Registry C for a hearing event.

2.  Registry B should return the file electronically in CEIS to Registry A.

3.  After accepting the returned file, Registry A should electronically transfer the file in CEIS to Registry C. They should include a comment in the \"Comments\" section in the Hearings Sent screen, indicating that Registry B will be sending the physical file to them.

4.  Registry B will send the physical file to Registry C, with a memo that indicates that Registry A will be transferring the file to them electronically in CEIS.

5.  After the hearing event, unless otherwise ordered, Registry C will electronically transfer the file back to Registry A and send the physical file to Registry A via house mail.



### Transfer out of Province

Although we do not connect to other provinces applications, we do have a means to capture a transfer within CEIS to ensure we know what happened to the file. We would transfer out just like normal, only difference is we will not get a received status back.

In the event this same file is returned from the other province and we need to accept it back -- connect with CEIS Support and we will reverse this transfer. If this happens, we need to make a notation in the File Details Comment section that it was transferred to another province and returned, in case there are further orders, documents or actions within the file from said province. We have a way of understanding the full story of the file.

This **does NOT** apply to situations where the court orders that two or more files be heard together for trial; in that case, the files remain independent of each other and are simply heard at the same time.

**Things to note:**

- Just like transfer for all purposes files -- appearances do not transfer

- Just like transfer for all purposes files -- you cannot update an amalgamated file

- Party details, counsel details and appearance details do not amalgamate, only documents and orders. Any additional information will need to be manually added.

- If transferring to another registry, at this point there is no "Accept" date, as it amalgamates same day, for physical mailing of files, we will recommend entering enter a comment about when the file was physically mailed and if there was a tracking number in the file details.

- We can amalgamate fully sealed files into sealed and non sealed files BUT we cannot amalgamate files with 1 or more individually sealed documents into a non-sealed file. *If you come across this before our fix, please amalgamate manually*.

- If you amalgamate in error, you will need to connect with CEIS Support to correct the files.

*In the event the Amalgamation Electronic Way* *does not work* -- **here is the manual process.**

1.  An order is made by the court that two or more files be amalgamated. (The judge will identify which of the files will be the lead file (File A), and will also identify the new style of cause.)

2.  Remove the original physical contents of File B (the secondary file) and place them in File A (the lead file). Leave a copy of the amalgamation order in File B.

3.  Notate on the File B file folder (the location to be determined by local registry practice) that the file has been amalgamated with File A (include file number).

4.  Locate File B in CEIS. In the *File Details* screen, enter a note in the Comments field that the file has been \"amalgamated with File A (include file number) pursuant to Order dated \[date\].\" Change the File Status to \"Inactive\".

5.  Locate File A in CEIS. In the *File Details* screen, enter a note in the Comments field that File B (include file number) has been \"amalgamated with this file pursuant to Order dated \[date\].\"

6.  In File A, click *Documents* in the left sidebar menu of CEIS and **manually** add all of the documents from File B into File A.

NOTE -- Best Practice regarding party\'s role changes: the new role type is added to that party rather than editing the original role type.

Some other examples of when a party\'s role may change are:

- Third Party Notice is filed - the defendant gets the additional role of third party.

- A transfer occurs from Supreme to Provincial, or Provincial to Supreme.

7.  If new documents are submitted with File B\'s file number, manually change the document to show File A\'s file number. Do not reject the documents because the file number is incorrect.

8.  All documents that are filed subsequent to the court order must be entered against File A.
